SOP-04 Python scriptingScope and overview

Scope and overview

The temview Python package controls the simulated microscope: it changes settings, records detector data as NumPy arrays with calibrations, runs analyses that report the simulator's true values, and sets hidden misalignments (challenges) that score an algorithm against the truth. The same script runs in three places.

Terms used

A challenge is a training task's hidden misalignment, set up for a script instead of a person. The knob is the setting a script reads and changes; the truth is the optics the simulator actually applies. During a challenge the two differ by the hidden amount, as on a misaligned instrument.

Rules

  • While a person is doing a training task in the exhibit, scripts cannot change settings. The exhibit refuses, so recorded practice stays human.
  • Challenge runs are never recorded or shared with the research dataset.
  • Ending a challenge restores the instrument as it was before the challenge.
  • In the IDE, the exhibit pauses while a script runs and redraws when it ends. Keep long loops on a desktop.
  • Live mode listens on 127.0.0.1 only, on the port temview-mcp uses (8790). Run one or the other, or choose another port.
Note. An algorithm that reads the score or the hidden values while it runs is not tested by the challenge. Use score() and reveal() only after the algorithm has finished.

Step 1

Run a first script in the exhibit

  1. Open the exhibit in a current browser and select the terminal button at the top of the controls (Fig. 12a), or Controls → Python scripting → Open the Python IDE (Fig. 12b), or press P.
  2. Wait for the status line to show the Python version. The first time, about 15 MB downloads; later it opens in a few seconds.
  3. Select Examples → Quick start, then Run (or Ctrl+Enter, ⌘+Enter on a Mac).
  4. The exhibit switches to HAADF STEM on SrTiO₃. The output shows the recorded image, its pixel size, and the probe profile (Fig. 12c).
  5. Edit the script and run it again. Save writes it as a .py file; Open loads one. Help lists the calls.

Result. The script changes the exhibit, and its output appears below the editor.

import temview as tv

tem = tv.connect()
tem.set(mode="stem", specimen="sto", kV=300, corrector=True, detector="haadf")
img = tem.acquire()
print(img, img.calibration)
tv.show(img, "HAADF, SrTiO3")
Note. The editor keeps your script in this browser between visits. Python runs on your computer; no code is sent anywhere.

Step 2

Install the package on a desktop

The headless backend runs the simulator's own JavaScript in Node.js, so the package is installed from a copy of the repository and stays linked to it.

git clone https://github.com/Advanced-EM/TEM-view
python -m venv .venv && source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e "TEM-view/tools/temview-py[live,plot,test]"
pytest TEM-view/tools/temview-py/tests                        # all tests should pass
python TEM-view/tools/temview-py/examples/quickstart.py

Headless

  1. Check Node.js: node --version must report 20 or later.
  2. In Python, tem = tv.connect() starts the simulator in a background Node process. It stops when the script ends, or with tem.close().
  3. Use it as a context manager to close it reliably: with tv.connect() as tem: …

Result. tem.info()["backend"] is "headless", and a typical acquisition returns in a fraction of a second.

Note. To use a copy of the repository somewhere else, set the environment variable TEMVIEW_ROOT to its folder.

Live (driving an open exhibit)

  1. Close any AI client that runs temview-mcp, or choose another port.
  2. Run the script. tv.connect("live") prints that it is waiting for the exhibit.
  3. In the exhibit, select Controls → Voice and agent → Connect agent within the timeout (120 s by default).
  4. The script continues, and the exhibit follows each call on screen.
tem = tv.connect("live", port=8790, timeout=120)

Result. The script prints “Exhibit connected.”, and the exhibit shows Agent connected.

Caution. Live mode listens on 127.0.0.1 only and accepts the exhibit's own site and localhost. Do not forward the port to a network.

Settings apply in a fixed order whatever order you write them: specimen, mode, then the optics. Loading a specimen applies its usual conditions (for example, the cryo specimen sets 300 kV and a cryo holder), so set those values after it or in the same call.

Errors. A refused or invalid call raises TemviewError with the reason, for example unknown setting focus or a training task is running.

Step 4

Test an automation algorithm with challenges

A challenge hides a misalignment, so the knob readings no longer show the true optics. The algorithm works only from what a real microscope gives it: images, FFTs and fits. Afterwards, score() grades the result against the truth. A fixed seed repeats the same misalignment, so algorithms are compared on the same cases.

  1. Start a challenge with a seed: tem.challenge("tem-focus-stig", seed=1).
  2. Run the algorithm. It may read state() (the knobs), acquire, and analyze, but not score() or reveal().
  3. When it stops, record tem.score().
  4. Repeat for a set of seeds, and report the scores together.
  5. Call tem.end_challenge() to restore the instrument.

The example: automatic focus and stigmation

examples/auto_focus_stig.py corrects defocus and two-fold astigmatism from Thon rings only:

  • It trusts a CTF fit only if it matches the rings well (correlation ≥ 0.4) and is more than 25 nm from focus, where there are enough rings.
  • Thon rings alone cannot always tell over- from underfocus. A known 20 nm focus step resolves the sign: if the measured defocus moves the other way, the sign was wrong.
  • The knobs are off by unknown amounts, so it moves them by the measured error, never to an absolute value.
  • Astigmatism is subtracted as a vector at twice its angle, with each step capped at 60 nm.

Lessons from building it. The first versions failed on half the seeds: fits taken too close to focus were trusted, the defocus sign was taken from a single fit, and one magnification was used for every case. Benchmarking on several seeds is what exposed each of these.

Step 5

Batch data and regression tests

A labelled dataset

Simulated data comes with exact ground truth, which makes it useful for training and testing analysis models. Run this headless:

import json, temview as tv

with tv.connect() as tem:
    tem.set(mode="tem", specimen="au", corrector=False, fov_nm=20)
    labels = []
    for i, df in enumerate(range(-150, -19, 10)):
        for a1 in (0, 5, 10, 20):
            tem.set(defocus_nm=df)
            tem.aberrations(A1=(a1, 30))
            tem.acquire().save(f"ctf_{i:03d}_{a1:02d}.npz")
            labels.append({"file": f"ctf_{i:03d}_{a1:02d}.npz",
                           "defocus_nm": df, "A1_nm": a1, "A1_deg": 30})
    json.dump(labels, open("labels.json", "w"), indent=1)

Each .npz carries the full instrument state in its metadata, so a label file is a convenience rather than the only record.

Reproducibility

  • Record tem.state() and tem.info() with every result.
  • Fix challenge seeds. Use realistic mode (realistic=True) when shot noise matters to the algorithm.
  • Note the repository commit (git rev-parse HEAD); the simulator improves between versions.

An algorithm as a regression test

Put the benchmark in a test so that changes to the algorithm or the simulator cannot silently make it worse:

# tests/test_autofocus.py
import pytest, temview as tv
from my_autofocus import run

@pytest.fixture(scope="module")
def tem():
    with tv.connect() as m:
        yield m

@pytest.mark.parametrize("seed", range(1, 9))
def test_autofocus(tem, seed):
    tem.challenge("tem-focus-stig", seed=seed)
    run(tem)
    assert tem.score()["score"] >= 85
    tem.end_challenge()

The TEM-view repository runs its own tests this way on every pull request (.github/workflows/tests.yml), with Node.js 20 and Python set up in the workflow.

Through-focus example. examples/through_focus.py steps the defocus from −120 to +40 nm and tabulates image contrast. On gold at 200 kV, contrast peaks near −60 nm, close to the Scherzer defocus of −65.8 nm.

Speed

A TEM or STEM acquisition takes tens of milliseconds, and a CTF fit about half a second. The simulator computes on the CPU in JavaScript. The calls do not depend on how it computes, so a future WebGPU backend could speed up the same scripts without changes; the IDE's status line shows whether the browser offers WebGPU.
